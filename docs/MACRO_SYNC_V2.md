# Версии и слияние макросов

Macros Sync v2 хранит библиотеку в `universal_macros.json`, а неизменяемые версии —
в соседнем каталоге `universal_macros.json.history`. Git и доступ в Интернет для работы не нужны.
Сервер, основной плагин и Companion нужно обновить на всех компьютерах до включения истории.
Старый сервер не знает о блокировках v2 и не должен работать с этой библиотекой.

## Работа через плагин

1. Укажите сервер и путь к общей папке. Нажмите **Включить историю**, просмотрите
   исходные макросы и подтвердите. Исходный JSON сохраняется отдельным снимком.
2. Отметьте универсальные макросы в текущей книге и выберите **Сохранить выбранные
   в библиотеку…**. Просмотрите код, свойства и результат. Эта операция не меняет книгу.
3. Для обратного направления выберите макросы библиотеки и **Применить к документу…**.
   Для выбранных GUID итогом предлагается текущая версия библиотеки, даже если
   менялась только книга. До записи сервер сохранит резервную копию, затем плагин
   проверит, что книга не изменилась после просмотра. После применения сохраните
   книгу средствами Р7.
4. При сохранении в библиотеку, если база неизвестна или правки пересекаются,
   выберите документ, библиотеку, отдельные конфликтные участки либо отредактируйте
   итоговый код и свойства.
   После ручной правки нажмите **Подтвердить итог этого макроса**.
5. **История библиотеки** позволяет просмотреть восстановление старой версии.
   Восстановление создаёт новую версию; последующая история не удаляется.

Выбор выполняется по макросам целиком. Свойство `guid` менять нельзя. Значение
`null` в итоговых свойствах означает удаление макроса. Изменения свойств видны
в панелях исходных версий и итоговых свойств. Код в интерфейсе не исполняется.

При открытии плагин не изменяет порядок макросов и разделитель. Флаги
«универсальный» и «не проверять» меняются только явным действием пользователя,
с проверкой актуальности документа. Боковая панель Companion и списки основного
плагина напрямую сравнивают макросы книги с текущей библиотекой по GUID: код и общие
свойства, независимо от сохранённой базы слияния. Локальные флаги книги не учитываются.
Макросы с флагом «не проверять» пропускаются. Отсутствие макроса в книге или библиотеке
показывается отдельно. Companion проверяет при открытии панели и по кнопке «Проверить»;
она показывает результат и не применяет изменения.

## База и правила слияния

Макросы сопоставляются по непустому уникальному GUID. При публикации в библиотеку
код сливается построчно относительно исходной версии. Независимые изменения
объединяются, пересекающиеся требуют решения пользователя. При применении к книге
итогом по умолчанию является библиотечная версия без слияния. `name`, `autostart`
и неизвестные общие свойства сравниваются отдельно. Переносы строк и пробелы
не игнорируются.

Поле `_r7Sync` макроса книги хранит `schemaVersion: 1`, `libraryId`, `revisionId`
и `base` — исходный макрос без локальных полей. При применении к книге базой становится
текущая версия библиотеки. Сохранение в библиотеку не меняет базу книги. `localStorage` хранит настройки,
а не базу синхронизации.

Если Р7 удаляет `_r7Sync`, следующий сеанс работает без известной базы: при
публикации разных существующих версий потребуется явный выбор. Немедленная потеря поля после записи
показывается в журнале. Сохранность поля после редактирования и повторного открытия
нужно проверить на используемой версии Р7.

Отсутствие макроса в книге не удаляет его из библиотеки. Удаление из библиотеки —
отдельная операция с просмотром. Удалённые макросы, для которых в книге сохранилась
база, остаются видны справа: удаление можно применить явно. При публикации конфликт
удаления с редактированием требует решения. Обычные макросы и локальный флаг
`isExcludedFromAutoSync` при загрузке сохраняются.

## API

Все методы используют POST и JSON. Расположение задают `directoryPath` и
`fileName` (только имя, без вложенного пути).

| Путь | Запрос / результат |
|---|---|
| `/macros/v2/state` | Расположение → `library`, `managed`, `externalChanges` |
| `/macros/v2/preview` | Операция и снимок документа → `token`, `operationId`, `expiresAt`, `changes` |
| `/macros/v2/apply` | Токен и решения → `revisionId`, `changed`; для книги также `document`, `expectedDocument`, `backupPath` |
| `/macros/v2/history` | Расположение → опубликованные версии от новой к старой |
| `/macros/v2/revision` | Расположение и `revisionId` → снимок опубликованной версии |

Пример просмотра:

```json
{
  "directoryPath": "D:\\shared",
  "fileName": "universal_macros.json",
  "action": "pull",
  "document": {
    "macrosArray": [
      {"guid": "one", "name": "One", "value": "original code", "isUniversal": true}
    ]
  },
  "selectedGuids": ["one"]
}
```

`document` — полный объект, полученный через GetMacros, включая неизвестные поля.
Операции: `push`, `pull`, `delete`, `restore`, `import`, `restoreDocument`.
Для `restore` требуется `revisionId`; для `restoreDocument` — `replacementDocument`
с полным объектом из резервной копии. `import` включает историю либо регистрирует
изменение файла сторонним редактором. `restore`, `import` и `restoreDocument`
применяются целиком и не принимают ручные разрешения.

Каждый элемент `changes` содержит GUID, имя, тип изменения, `base`, `document`,
`library`, `result`, список конфликтующих полей `conflicts`, построчный `diff`
и `chunks` для выбора конфликтных участков. В `restore` и `import` поле `document`
обозначает входящую версию, `library` — текущую. В `restoreDocument` это соответственно
резервная копия и текущая книга. `null` обозначает отсутствие макроса.

Применение:

```json
{
  "directoryPath": "D:\\shared",
  "fileName": "universal_macros.json",
  "token": "token-from-preview",
  "operationId": "uuid-from-preview",
  "selectedGuids": ["one"],
  "resolutions": {
    "one": {"macro": {"guid": "one", "name": "One", "value": "resolved code"}}
  },
  "comment": "Исправлена обработка ошибок",
  "backupDirectory": ""
}
```

`resolutions` обязателен для выбранных конфликтующих макросов. Для удаления через
разрешение конфликта передаётся `{"macro": null}`. Токены действуют 30 минут и теряются
при перезапуске сервера. Новый просмотр не пишет файлы. Повтор уже опубликованной
операции определяется по `operationId` в истории, в том числе после перезапуска.
При потере ответа повторяйте исходный запрос без изменения решений.

`409` означает устаревший просмотр, занятую библиотеку, внешнее изменение,
необходимость обновить старый клиент либо проблему целостности истории.
При `400` исправьте запрос; при `409` перечитайте данные и пересчитайте результат.
Старый `/macros/sync` работает только с неверсионными файлами. Запись управляемой
библиотеки и истории через `/files/write` запрещена.

## Сохранность и восстановление

Библиотека получает `_r7Library` с `schemaVersion: 1`, `libraryId`, `revisionId`.
Снимки `<uuid>.json` содержат родителя, библиотеку, дату UTC, пользователя/компьютер
сервера, комментарий и идентификатор операции. Это информация для истории,
не удостоверенная подпись автора. Автоматического удаления версий нет.

На время записи используется локальная блокировка и файловая блокировка
`<имя-файла>.r7lock`. Под блокировкой повторно проверяются исходные байты файла.
Подтверждённая операция записывается в `.pending.json`, затем сохраняются снимки
и атомарно заменяется библиотека. Следующий запрос применения завершает оставшуюся
подтверждённую операцию из журнала. История отображает только цепочку, на которую
указывает текущий JSON. Неопубликованные снимки не считаются коммитами.

Если файл изменён во время незавершённой операции, автоматическое восстановление
останавливается. Сохраните копию всей папки, остановите писателей и сопоставьте
текущий JSON, `.pending.json` и снимки. Не удаляйте журнал для обхода ошибки.
При утрате корневых метаданных восстановите JSON из поля `library` известного
снимка истории, предварительно сохранив повреждённый файл. Не редактируйте историю.

Атомарная замена не подменяется обычной перезаписью. Сетевая папка должна поддерживать
блокировки между компьютерами и атомарную замену. Это необходимо проверить на реальном
SMB/NFS-хранилище. Редакторы и старые серверы, не соблюдающие протокол блокировок,
не должны одновременно записывать библиотеку. Хеш обнаруживает внешнюю правку
между операциями, но не делает сторонний редактор участником блокировки.

Перед изменением кода документа создаётся `macros-<operationId>.json` с полным
содержимым GetMacros. Используется указанная папка резервных копий, иначе
`macro-backups` в папке состояния R7LocalServer. Ошибка копирования отменяет применение.
Кнопка **Восстановить копию документа** принимает полный путь; последняя копия
подставляется автоматически. Перед восстановлением также создаётся копия текущего
состояния. Резервные копии содержат макросы, а не ячейки или весь файл книги.

## Проверки перед использованием общей библиотеки

Автоматические проверки:

```powershell
.\gradlew.bat :composeApp:jvmTest --console=plain
node --test plugins/tests/*.test.cjs
```

Сборка устанавливаемых плагинов: `gradlew.bat :composeApp:packageMacroPlugins`.
Файлы `.plugin` создаются в `composeApp/build/distributions/plugins`.

В Р7 и на двух компьютерах с общей папкой:

1. Загрузить макрос, изменить его, сохранить и повторно открыть книгу; проверить
   сохранность `_r7Sync` и корректность сравнения. Перенести книгу на второй компьютер.
2. Независимо изменить разные строки в книге и библиотеке; проверить объединённый
   результат, затем изменить одну строку с двух сторон и разрешить конфликт.
3. Открыть один просмотр на двух компьютерах и подтвердить разные изменения:
   вторая операция должна запросить пересчёт.
4. Прервать сеть при сохранении, восстановить доступ и повторить исходный запрос.
   Убедиться, что библиотека читается и версия опубликована только один раз.
5. Отменить просмотр, проверить неизменность книги и файла. Проверить восстановление
   старой версии и резервной копии документа, а также отсутствие записей Companion.

Текстовое слияние не проверяет правильность выполнения самого макроса.
